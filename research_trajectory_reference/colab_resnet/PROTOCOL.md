# E7: ResNet-18 на полном CIFAR-10 — протокол (записан до запуска)

## Вопрос

Переносится ли результат E5 и онлайн-детектор E6 с маленькой CNN
(15 тыс. параметров) на реальную сеть? Проверяются два сценария:

- **scratch** — обучение ResNet-18 с нуля;
- **finetune** — дообучение ImageNet-предобученной ResNet-18. Это практический
  сценарий transfer learning.

## Что зафиксировано заранее и не подбирается на E7

- **Наблюдатель** — норма всех параметров на каждом шаге. Считается за O(P) на GPU,
  прохода сети не требует.
- **MG**: E = 20, τ = 1, k = 20, исключение Тейлера на размах вектора задержек;
  окно 1 000 шагов, шаг окон 500. Реализация — `code/actdim`, без изменений.
- **Сравнение «до/после»**: медиана MG по окнам внутри [event − 2 000, event)
  против медианы по окнам, начинающимся в [event + 1 000, event + 5 000].
- **Детектор** — правило из `detector_rule.json`, откалиброванное на CPU-сидах E4
  (MG: M = 2, B = 3, δ = 0.088). Тревога — при D_k < −δ. Попадание — первая тревога
  в пределах 5 000 шагов после события; тревога до события или в запуске без события
  считается ложной.
- **Независимое подтверждение**: PR ковариации обновлений параметров, по
  CountSketch до 1 024 координат, в том же окне, и средний размер обновления.

## Обучение

- SGD, momentum 0.9, weight decay 5·10⁻⁴, lr 0.02, батч 128 с возвращением, без
  аугментаций, AMP.
- 10 000 шагов, событие на шаге 4 000.
- Сиды 20, 21, 22 — ранее не использовались.
- finetune: вход 64×64, нормировка ImageNet, заменён только `fc`.

## Рукава

| рукав | что происходит на шаге 4 000 | ожидание |
|---|---|---|
| base | ничего | нет тревоги |
| batch_up | батч ×4 (меньше шума) | нет тревоги |
| lr10 / lr100 | lr ÷ 10 / ÷ 100 | тревога |
| freeze_head | учится только `fc` (≈ 5 тыс. из 11 млн параметров) | тревога |
| prune80 / prune95 | прунинг 80 % / 95 % весов | тревога |
| scale / smooth | контроли наблюдателя на логе base | нет тревоги |

## Предсказания

- **P1.** Медианное изменение MG у lr100, freeze_head, prune80 и prune95 ниже −8.8 %
  (порог детектора); у base, batch_up, scale, smooth — выше −5 %.
- **P2.** Детектор с замороженным правилом ловит ≥ 75 % запусков с сильными
  событиями (lr10, lr100, freeze_head, prune80, prune95) и даёт не больше одной
  ложной тревоги на все запуски без упрощения.
- **P3.** В обоих сценариях изменение MG коррелирует по запускам с изменением PR
  обновлений положительно.

Что бы ни получилось, отчитываемся обо всех рукавах и сидах. Если правило детектора
на E7 не переносится, повторная калибровка на E7 допустима только как вторичный
анализ с явной пометкой.
