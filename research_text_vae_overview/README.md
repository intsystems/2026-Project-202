# Итоговая сводка по текстовому VAE

Откройте `report_ru.pdf`: пять страниц на русском, охватывающие всю завершённую серию. Редактируемый текст — `report_ru.md`. Новые модели при подготовке сводки не обучались. Старые отчёты и результаты не изменены.

## Содержание

- Парный эксперимент: пилот 0, проверочные сиды 1–9; основная серия и расширение объединены.
- Контроль сохранения кода: неудачный пилот encoder5 и free bits на тех же десяти инициализациях.
- Чувствительность к размеру окна/задержке, альтернативный мини-батчевый лог, STD и спектральная энтропия, контроль масштаба и суррогаты.
- Циклическое обучение: пилот 100, проверка 101–109; все три бюджета мониторинга и локальный бенчмарк стоимости.

Главные положительные результаты — согласованное с независимыми диагностиками падение MG и отличие ветки с сохранением кода на 9/9 проверочных сидах. Результат циклического мониторинга и стоимость получения лога приведены полностью, поэтому преимущество по сквозной скорости или над всеми конкурентами не заявляется.

## Происхождение чисел

Все пути ниже относительно корня проекта (или корня распакованного архива).

| Часть отчёта | Основные источники |
| --- | --- |
| Постановка | `research_text_vae/PROTOCOL.md`, `run.py`, `data/selection.json` |
| Парное обучение | `research_text_vae/all_seeds.csv`, `summary.json`, `series_audit.json`, исходные `reference.csv` и `windows.csv` каждого сида |
| Окна и наблюдатель | `research_text_vae/all_seeds_sensitivity.csv`, `observer_controls.csv`, `minibatch_windows.csv`, `secondary_summary.json` внутри каталогов сидов |
| Сохранение | `research_text_vae/protection/PROTOCOL.md`, `selection.json`, `all_seeds.csv`, `sensitivity.csv`, `audit.json`; `encoder5/seed0` и `freebits/seed0`–`seed9` |
| Циклический мониторинг | `research_text_vae/cyclical/PROTOCOL.md`, `selection.json`, `all_scores.csv`, `summary.json`, `events_by_seed.csv`, `audit.json` |
| Время | `research_text_vae/cyclical/benchmark.json`, `costs.csv`, `benchmark.py` |

`source_manifest.json` содержит SHA256 файлов, непосредственно использованных при построении сводных таблиц. `archive_manifest.json` перечисляет содержимое итогового архива и его контрольные суммы; сам манифест в собственный список не включён.

`collect_evidence.py` заново сверяет поздние медианы MI, реакции на код и MG по исходным диагностическим таблицам всех десяти сидов; строит таблицы всех бюджетов по девяти проверочным сидам. `tables/` содержит результаты этой сверки, включая все индивидуальные сиды. Таблицы отчёта округлены; CSV сохраняют полную точность. Bootstrap-интервалы взяты из исходных сводок с 20 000 повторов по сиду, а не по отдельным окнам.

## Пересборка отчёта

Нужны Python с numpy, pandas, matplotlib; XeLaTeX, шрифт Times New Roman и стандартные LaTeX-пакеты fontspec, polyglossia, amsmath, booktabs, tabularx, graphicx, geometry, hyperref, titlesec. В корне проекта:

```powershell
python research_text_vae_overview/collect_evidence.py
python research_text_vae_overview/figures.py
python research_text_vae_overview/build_report.py
python research_text_vae_overview/package_report.py
```

В текущем рабочем окружении вместо `python` использовался `.venv_walker\Scripts\python.exe`. `build_report.py` преобразует Markdown в TeX, дважды запускает XeLaTeX и проверяет ошибки, отсутствующие символы и переполнение строк. Формулы в Markdown записаны в окружениях `$...$` и `$$...$$`; для просмотра с гарантированной вёрсткой используйте PDF.

## Состав архива

`vae_complete_report.zip` содержит готовый PDF, текст и TeX, векторные графики, скрипты сводки, первичные числовые логи/диагностики, протоколы, конфигурации и исходные скрипты VAE. Он предназначен для проверки отчёта и повторного построения таблиц/рисунков без обучения. Веса моделей, исходные тексты корпуса, окружения Python и архивные дубликаты `initial_three`/`before_protection` не включены. Поэтому архив не является автономным комплектом для повторного обучения или пересчёта эталонных метрик из весов; веса и корпус остаются в исходных папках проекта. Скрипты экспериментов могут импортировать общую библиотеку `code/actdim`, которая также остаётся в проекте.

## Проверка готового документа

PDF содержит пять страниц. При сборке не обнаружены ошибки LaTeX, отсутствующие символы и переполнения. Все пять страниц просмотрены после рендеринга: формулы, таблицы и графики находятся внутри страницы. Проверка ZIP и контрольных сумм выполняется скриптом упаковки.
