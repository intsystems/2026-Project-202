5.  How many runs would settle this?
===============================================================================
  The evaluation set is 3 generalising probed runs and 3 controls; the drop
  conjunct alone reaches 11 and 3. Binomial arithmetic on what that supports.

  11/11 detections -> recall 95% interval [0.80, 1.00]
  10/11 detections -> recall 95% interval [0.65, 0.99]
  3/3 detections -> recall 95% interval [0.46, 1.00]

  0/3 false alarms -> FP rate 95% interval [0.00, 0.54]
  0/10 false alarms -> FP rate 95% interval [0.00, 0.22]
  0/40 false alarms -> FP rate 95% interval [0.00, 0.06]

  Three clean controls bound the false-alarm rate only below about 0.6. A
  precursor claim needs the interval below the base rate it is competing with,
  which for 'does this run generalise' is roughly one half.

8.  Does the detector predict t_gen, or just count steps since t_mem?
===============================================================================
  A precursor is useful because it fires a knowable distance before the event.
  If instead it fires a fixed distance AFTER memorisation, the 'lead' is just
  the gap minus a constant -- and the gap is what nobody knows in advance.

  Capping the detector at t_gen -- as sections 2, 4 and 7 do, to keep it from
  reading past the event -- also throws away every run that would have fired
  late. Correlating a lead time over the survivors is then circular. Below the
  detector instead runs to the end of training, so every generalising run
  contributes a firing step whether or not it beat t_gen.

     lead before t_gen   -9430-9410   (spread  1.0x)   rho with gap +0.92
